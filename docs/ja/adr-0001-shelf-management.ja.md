# ADR-0001: 棚の編集機能を url-shelf 内に持つ

> Date: 2026-07-26
> Status: Accepted（2026-07-26 改訂: 並べ替えを保留から実装へ）

## 背景

RFP の時点では、url-shelf は「読んで開く」だけの道具だった。棚の再編成は Finder で
行う前提で、それはツールにロックインされないという設計思想の帰結でもあった。

実際に自分の `.webloc` 群を棚として使ってみると、Finder では埋まらない穴が見えた。

| 操作 | Finder | 評価 |
|---|---|---|
| フォルダの作成・リネーム・移動・削除 | できる | アプリ内で完結すると便利、という程度 |
| webloc の移動・削除 | できる | 同上 |
| **エントリの URL / 開き方 / ブラウザ指定の編集** | **できない**（plist の手編集が必要） | **本質的な穴** |
| 並び順プレフィックスの維持 | できるが手作業 | 苦痛 |

つまり中核は「Finder が触れないメタデータ」であり、ファイル操作はそれと同じ画面から
できると自然、という構造になっている。

## 決定

**Shelf ウィンドウ（ツリー＋インスペクタの 2 ペイン）を追加する。**

- 左ペインに棚のツリー全体、右ペインに選択対象のインスペクタ
- エントリのインスペクタ: 表示名 / URL / 配置フォルダ / 開き方 / ブラウザ指定
- フォルダのインスペクタ: 表示名 / 配置フォルダ / `.url-shelf.toml` の既定値
- 変更は即時反映（保存ボタンを置かない）。テキスト欄は Return またはフォーカス喪失で確定
- 再配置は**ツリー内のドラッグ&ドロップ**と、インスペクタのフォルダピッカーの両方で行う。
  行の上端/下端に落とすと**並べ替え**、フォルダの中央に落とすと**そのフォルダへ移動**
- 削除は **`FileManager.trashItem` でゴミ箱へ**。`unlink` は使わない
- 各操作の後にツリーを読み直す

`Add URL` ウィンドウは維持する。「今見ている URL をさっと放り込む」のは編集作業とは
別の行為であり、クリップボード初期値付きの軽量ウィンドウのほうが速い。

## 却下・保留した選択肢

**ドラッグでの並べ替え（当初は保留 → 2026-07-26 に実装）**: 移動だけを実装した状態は
「ドラッグできる場所とできない場所がある」という中途半端な操作感になったため、実装に切り替えた。
並び順はファイル名の数字プレフィックスで表現されているので、並べ替えは必然的に
**ファイル名のリネーム**を伴う。以下の形で危険を抑えた。

- **フォルダ単位で全件採番し直す**（`010_`, `020_`, …）。一部だけ振り直すと、プレフィックスの
  無いファイルが名前順に並ぶため、意図した順序が保証できない
- 刻みは 10。Finder 側で手動で間に挿入する余地を残すため
- プレフィックスは**3 桁まで**。4 桁は年号と区別できず、`DisplayName` が意図的に
  順序プレフィックスとして扱わない。1 フォルダ 99 件を超えたら刻みを 1 に、
  999 件を超えたら並べ替えを拒否する
- リネームは**2 段階**（全件を隠しファイル名へ退避 → 最終名へ）。`010_A` と `020_B` の
  入れ替えのように名前が衝突する操作でファイルを失わないため。2 段目で失敗したら退避分を戻す
- ファイルは消えない。順序が気に入らなければドラッグし直せばよく、Finder でリネームしてもよい

**Settings ウィンドウ内のタブ（却下）**: 設定の変更とデータの編集は性質が違う。
[Add URL を Settings から分離した](../en/url-shelf-rfp.md) のと同じ理由で、同居させない。

**メニューの右クリックのみ（却下）**: 軽量だが、ツリー全体を見ながらの再編成ができない。

**独自のインデックス/DB を持つ（却下）**: 編集機能を入れてもファイルシステムが唯一の正で
あることは変えない。アプリの外で棚をいじっても壊れない性質は、この道具の存在理由そのもの。

## 帰結

- url-shelf は「ランチャー」から「ランチャー＋管理」になる。README の説明も変わる
- Finder との併用は引き続き壊れない。アプリ内操作も Finder 操作も同じ結果になる
- 削除がゴミ箱経由になるため、誤操作は Finder から復元できる
- ファイル操作は protocol (`ShelfEditing`) の背後に置き、単体テスト可能にする
